Chapter 1

About WorkMan

WorkMan connects clients with verified local technicians and covers the whole service journey — not just a directory.

Discovery→Verification→Chat→Booking→Transport payment→Live tracking→Service→Confirmation→Rating→History

The three roles

RoleWhat they can do
ClientSearch and filter technicians, view profiles, chat, book (manually or with the AI booking assistant), pay the transport fee, track the technician live, confirm completion, rate and review, save favourites, report issues.
Technician
(called “provider” in the code)		Build a professional profile (services, prices, service areas, working hours), upload an ID for verification, switch availability on/off, accept or reject bookings, set transport fees, share live GPS location, mark jobs done, view service history.
AdministratorApprove or reject technicians, manage users (deactivate / reactivate), manage service categories, monitor bookings, moderate reviews and resolve reported issues.

How the pieces fit together

PieceTechnologyAddressFolder / role
DatabaseMySQL 8 / MariaDB (recommended) or SQLitelocalhost:3306Stores users, bookings, messages, payments, reviews…
BackendLaravel 13 REST API (PHP 8.3+)localhost:8000backend/ — all endpoints live under /api
FrontendReact 19 + Vite single-page applocalhost:5173frontend/ — the website you open in the browser

The browser only talks to the frontend at localhost:5173. Vite forwards (proxies) every request that starts with /api or /storage to the backend on port 8000, so no CORS setup is needed during development.

Chapter 4 · Step 1 of 3

Start the database

The backend needs a running database before it can create its tables. MySQL (or MariaDB) is the recommended option.

Why MySQL is recommended

The backend .env.example defaults to SQLite, but one migration (2026_09_12_151000_expand_payment_statuses_for_escrow.php) runs a MySQL-only ALTER TABLE … MODIFY … ENUM statement. On SQLite, php artisan migrate stops with an error at that file. Use MySQL/MariaDB to avoid this, or see “Option B” below.

Option A — MySQL / MariaDB (recommended)

1Start the MySQL server

Windows — XAMPP
  1. Open the XAMPP Control Panel.
  2. Click Start next to MySQL. It turns green and shows port 3306.
  3. (Optional) Click Start next to Apache too if you want to use phpMyAdmin.
macOS / Linux
# macOS (Homebrew)
$ brew services start mysql
# Ubuntu / Debian
$ sudo systemctl start mysql

2Create an empty database called workman

Either open phpMyAdmin (http://localhost/phpmyadmin) → New → type workman → collation utf8mb4_unicode_ci → Create, or use the terminal:

$ mysql -u root -p
-- (XAMPP: the root password is empty, just press Enter)
mysql> CREATE DATABASE workman CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
mysql> EXIT;

3Point the backend at MySQL

After you create backend/.env (Chapter 5, step 2), replace the two SQLite lines with:

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=workman
DB_USERNAME=root
DB_PASSWORD=          # empty on XAMPP; otherwise your MySQL password
Good to know

You do not create any tables by hand. Laravel creates all of them (users, bookings, payments, messages, reviews, sessions, cache, jobs…) when you run php artisan migrate --seed in the next chapter.

Option B — SQLite (file-based, no server)

SQLite stores the whole database in a single file, backend/database/database.sqlite, so there is no server to start. This is the default in .env.example:

DB_CONNECTION=sqlite
DB_DATABASE=database/database.sqlite
# create the empty database file (from the backend/ folder)
$ touch database/database.sqlite                 # macOS / Linux
> type nul > database\database.sqlite            # Windows (cmd)
Known limitation

Because of the MySQL-only migration mentioned above, php artisan migrate will fail on SQLite until that migration is made database-aware (for example, skipping the ALTER TABLE when DB::getDriverName() === 'sqlite'). Use Option A unless that has been fixed.

Chapter 5 · Step 2 of 3

Start the backend

The Laravel API runs on http://127.0.0.1:8000. Open a terminal in the project folder — this is Terminal 1.

1Install the PHP dependencies

$ cd backend
$ composer install

2Create the environment file

$ cp .env.example .env             # macOS / Linux / Git Bash
> copy .env.example .env           # Windows (cmd / PowerShell)

Now open backend/.env in a text editor and set the database lines as described in Chapter 4 (MySQL recommended). The other important values are already filled in:

VariableDefaultMeaning
APP_URLhttp://localhost:8000Where the API runs.
FRONTEND_URLhttp://localhost:5173Where the website runs (used for CORS).
DB_*SQLiteDatabase connection — change to MySQL.
AI_API_KEYemptyOptional — enables AI photo diagnosis (Chapter 9).

3Generate the application key

$ php artisan key:generate

4Create the tables and load the demo data

$ php artisan migrate --seed

This runs every migration in database/migrations/ and then DatabaseSeeder, which creates the demo accounts (Chapter 8), service categories, technician profiles and sample bookings at every stage of the lifecycle.

5Link the storage folder (for uploads)

$ php artisan storage:link

ID documents and booking photos are saved to storage/app/public. This command makes them reachable at /storage/… so administrators can open uploaded ID documents.

6Start the API server

$ php artisan serve
   INFO  Server running on [http://127.0.0.1:8000].

Leave this terminal open — closing it stops the backend.

Check that it works

Open http://127.0.0.1:8000/api/health in your browser. You should see a small JSON response with "status": "ok". http://127.0.0.1:8000/api/categories should list the service categories (Plumbing, Electrical work, Carpentry, Gas delivery, Laundry).

Useful backend commands

CommandWhat it does
php artisan migrate:fresh --seedDeletes every table, recreates them and reloads the demo data — a full reset.
php artisan serve --port=8080Run on another port (then update the proxy in frontend/vite.config.js).
php artisan route:list --path=apiLists every API endpoint.
php artisan config:clearReloads .env after you change it.
php artisan testRuns the PHPUnit test suite.
Chapter 6 · Step 3 of 3

Start the frontend

The React website runs on http://localhost:5173. Open a second terminal (Terminal 2) in the project folder; keep the backend terminal running.

1Install the JavaScript dependencies

$ cd frontend
$ npm install

2Check the environment file

frontend/.env already exists and contains a single line — you normally do not need to change it:

VITE_API_BASE_URL=/api

If the file is missing, copy it from .env.example (cp .env.example .env).

3Start the development server

$ npm run dev

  VITE v8.x  ready in 250 ms
  ➜  Local:   http://localhost:5173/
  ➜  Network: http://192.168.x.x:5173/

4Open the application

Go to http://localhost:5173 in Chrome, Edge or Firefox and log in with one of the demo accounts from Chapter 8 (for example client@workman.local / password).

How the frontend reaches the backend

frontend/vite.config.js proxies /api and /storage to http://127.0.0.1:8000. The server also listens on all network interfaces (host: '0.0.0.0'), so you can open the Network address on a phone connected to the same Wi-Fi — handy for testing live GPS tracking.

Other frontend commands

CommandWhat it does
npm run buildBuilds an optimised production version into frontend/dist/.
npm run previewServes the production build locally for a final check.
npm run lintChecks the code with ESLint.

Alternative: preview without PHP or a database (mock API)

If you only want to look at the interface, the frontend ships with a zero-dependency Node.js server that imitates the real API with the same demo data. Use it instead of the backend and database:

$ cd frontend
$ node dev/mock-api.mjs            # fake API on http://127.0.0.1:8000/api
$ node dev/mock-api.mjs --fresh    # same, but reset to the original demo data
# then, in another terminal:
$ npm run dev

The mock saves its state in frontend/dev/.mock-state.json. The screenshots in Part 2 of this guide were captured this way. Do not run the mock API and php artisan serve at the same time — both use port 8000.

Chapter 9

Optional: AI photo diagnosis

In the Book with AI assistant, clients can attach a photo of the problem and ask for an AI analysis. This calls an external vision model from the backend.

Everything else works without it. To enable it, add a key to backend/.env and restart php artisan serve:

AI_PROVIDER=openrouter                     # or: groq
AI_API_KEY=your-provider-key-here
AI_MODEL=google/gemini-2.0-flash-exp:free  # any vision model
AI_CA_BUNDLE=storage/app/cacert.pem        # optional
Keep the key secret

The key belongs only in backend/.env — never in frontend/.env (anything starting with VITE_ is sent to the browser). Without a key, the assistant shows “AI diagnosis is not configured”.

Troubleshooting

ProblemSolution
php or composer is “not recognized”Add PHP (e.g. C:\xampp\php) and Composer to your system PATH, then open a new terminal.
composer install complains about the PHP version or a missing extensionUse PHP 8.3+. Enable the missing extension (e.g. extension=fileinfo, extension=pdo_mysql) in php.ini.
SQLSTATE[HY000] [2002] Connection refusedMySQL is not running — start it in XAMPP. Check DB_HOST/DB_PORT in .env.
Unknown database 'workman'Create the database first (Chapter 4, step 2).
Access denied for user 'root'Set the correct DB_USERNAME / DB_PASSWORD, then run php artisan config:clear.
Migration fails with near "MODIFY": syntax errorYou are on SQLite. Switch to MySQL (Chapter 4, Option A), then run php artisan migrate:fresh --seed.
No application encryption key has been specifiedRun php artisan key:generate.
Login fails / the page shows network errorsThe backend is not running on port 8000. Start php artisan serve and check /api/health.
“Your account has been deactivated”An administrator deactivated this user. Reactivate it in Users, or reset the data with migrate:fresh --seed.
Port 5173 or 8000 already in useStop the other program (or an old terminal). Vite will offer the next free port automatically.
npm run dev fails with a Node version errorUpgrade Node.js to 20.19+ or 22.12+.
Uploaded ID documents give 404Run php artisan storage:link.
The tracking map is greyMap tiles come from OpenStreetMap — an internet connection is required. Allow location access when the browser asks.
The browser does not ask for location / sharing failsBrowsers only allow GPS on localhost or HTTPS. When testing on a phone via the Network IP, use an HTTPS tunnel.

Chapter 13 · Role guide

Client guide

Find a verified technician, book, pay the transport fee, follow the technician and rate the job. Try it with client@workman.local.

13.1 Overview

The Overview (Figure 4) is your home page. It shows:

  • Four counters — total bookings, completed jobs, unread messages and favourite technicians. Click any of them to open the matching page.
  • Next booking — your upcoming appointment with its status, date and transport fee, plus Manage booking.
  • Verified technicians near you — quick links to top-rated professionals. See all opens the search.
  • The Find a technician shortcut in the welcome banner.

13.2 Find a technician

Open Find a technician in the sidebar. Only technicians approved by an administrator appear here. Combine any of these filters — the results update as you type:

FilterUse it to…
What do you need?Search by technician name or service (e.g. “leak”, “Fatou”).
City or neighborhoodOnly show technicians who work in that area (e.g. Douala, Akwa).
All servicesLimit to one category (Plumbing, Electrical work, Carpentry…).
Any ratingShow only technicians rated 3★, 4★ or 4.5★ and up.
Available nowHide technicians who switched their availability off.

On each card, click the heart to save the technician to your favourites, or View profile to open the full profile.

13.3 Technician profile

The profile shows everything you need to decide: the Verified technician badge, bio, rating, years of experience, cities, availability, services with starting prices, weekly working hours, service areas and recent reviews. The action buttons at the top right:

  • ♥ — add / remove from favourites.
  • Chat — opens a private conversation with the technician in Messages. Use it to describe the problem before booking.
  • Book — opens the booking form (13.4).
  • Book with AI — lets the booking assistant prepare the request for you (13.5).

13.4 Booking a technician

  1. Click Book on the technician's profile.
  2. Choose the Service you need.
  3. Pick the Preferred date and time. It must fall inside the technician's working hours and not clash with another booking — otherwise you'll see an error explaining why.
  4. Enter the Service city and Service address (street, building, landmark).
  5. Choose the expected Duration.
  6. Describe the job in What do you need help with? and optionally attach a photo or video.
  7. Click Send booking request. The technician is notified and the booking appears in My bookings as Pending.
How payment works

You do not pay when you book. The technician sets a transport fee when they accept, and you pay it through WorkMan with mobile money. The service price itself is agreed after the technician has diagnosed the problem.

13.5 Booking with the AI assistant

Book with AI opens a short chat that asks four questions — the problem, the address, when you want the visit and how urgent it is. It then suggests the best matching service from that technician. You can attach a photo or video and click Analyze image with AI for a diagnosis (requires the AI key, Chapter 9). Click Use this booking to copy everything into the booking form, check it, and send it. Start over resets the conversation.

13.6 My bookings

Use the tabs at the top to filter by status: All, Pending, Accepted, In progress, Awaiting confirmation, Completed, Cancelled, Rejected, and Payments (your payment history). The buttons on each card change with the booking's status:

StatusWhat it meansButtons you'll see
PendingWaiting for the technician to answer.Cancel request
AcceptedThe technician accepted and set a transport fee.Pay transport fee → then Release transport payment; Track technician
In progressThe technician has started the job.Track technician
Awaiting confirmationThe technician marked the work as done.Confirm completion
CompletedYou confirmed the job.Star rating + review form; Pay service fee; Clear booking
Cancelled / RejectedYou cancelled, or the technician declined.Clear booking

Every card also has Message (chat with the technician) and Report issue.

13.7 Paying the transport fee (escrow)

  1. On an Accepted booking, click Pay transport fee.
  2. Check the amount due, choose MTN Mobile Money or Orange Money and enter your mobile money number.
  3. Click Pay 1,500 FCFA (the button shows the amount). The money is held in escrow by WorkMan — the technician can see it has been paid, but does not receive it yet.
  4. When the technician arrives, click Release transport payment. The technician can now start the job.
Development note

In local development the mobile money confirmation is simulated — no real money moves. In production it would be confirmed by the MTN MoMo / Orange Money webhook. Never share your mobile money PIN in chat.

13.8 Live tracking

For Accepted and In progress bookings, click Track technician. The map shows the technician's shared GPS position and, if you click Share my location and allow the browser's location prompt, your own position — the badge then shows how many kilometres apart you are. Click Stop sharing at any time; sharing is only possible while the booking is active.

13.9 Confirming, paying the service and reviewing

  1. When the technician marks the job done, the booking becomes Awaiting confirmation.
  2. Check the work, then click Confirm completion. (If a transport fee exists, it must be paid and released first — the button stays disabled with a reminder until then.)
  3. On the Completed booking, click the stars (1–5), write a short comment and click Submit review. It appears on the technician's profile and updates their rating.
  4. If the technician listed a starting price, Pay service fee lets you pay it through WorkMan the same way as the transport fee.

The Payments tab lists every transport and service payment with its status: Pending, Held in escrow, Released or Paid.

13.10 Reporting an issue

Click Report issue on any booking, choose the type — Inappropriate behavior, Fake or misleading profile, Payment issue, No-show at appointment, Safety concern or Other — describe what happened and submit. The WorkMan administrators receive it in Reports & issues.

13.11 Favorites

Every technician you hearted appears here with View profile and Message shortcuts. Click the heart again to remove them.

13.12 Messages

The left column lists your conversations; click one to read it. Type in Write a message… and press Send (or Enter). New conversations are started from a technician's profile (Chat), a favourite, or a booking (Message). Technicians use exactly the same page.

13.13 Assistant

The Assistant page answers common questions instantly — how to book, where your booking is, how to pay, how to cancel. Click a suggested question or type your own. (Technicians get questions about accepting jobs, availability and verification.)

13.14 Settings & identity verification

  • Your information — update your full name, phone, city and address, then click Save changes.
  • Identity verification — upload a photo of your National ID card or passport (JPG, PNG or PDF, up to 5 MB) and click Upload ID document. The status changes from Unverified to Pending until reviewed.
Chapter 14 · Role guide

Technician guide

Set up your professional profile, get verified, and manage jobs from request to completion. Try it with michael@workman.local.

14.1 Overview, verification status & availability

  • The verification banner tells you where you stand: Pending — you are not visible to clients yet; Verified ✓ — clients can find you; Rejected — review your profile and contact the administrator.
  • The Available for new requests switch controls whether you appear in client searches. Turn it off when you are busy or on leave.
  • Counters for pending requests, upcoming jobs, your rating and number of reviews, plus lists of Pending requests and Next jobs.

14.2 Setting up your profile — My profile

Complete every section — a full profile gets approved faster and receives more bookings. Each section has its own save button.

SectionWhat to do
Personal informationFull name, phone, years of experience and a short bio. Click Save basics.
Identity verificationUpload your National ID or passport (JPG, PNG, PDF, max 5 MB) with Upload ID document. An administrator checks it before approving you.
Services you offerPick a category, enter a service name (e.g. “Leak repair”) and a starting price in FCFA, then Add service. Remove a service with its ✕. If your trade is missing, type it in Request a custom category — an administrator will review it.
Where you workAdd each city and (optionally) neighbourhood you cover, e.g. Douala · Akwa, with Add service area. Clients filter by these.
Your weekly scheduleSwitch each day on/off and set start and end times, then Save working hours. Clients can only book inside these hours.

14.3 Handling job requests — Job requests

Filter with the tabs All, Pending, Accepted, In progress, Awaiting confirmation, Completed. Then work through each job:

  1. Accept or reject. On a Pending request click Accept, enter the transport fee (FCFA) the client must pay before you travel, and confirm with Accept booking. Or click Reject.
  2. Wait for payment. The client pays the transport fee into escrow and releases it when you arrive. Until then the card shows “Waiting for the client to release the transport payment”.
  3. Start the job. Click Start job — the status becomes In progress.
  4. Share your location while travelling with Share location → Share my location (allow the browser prompt) so the client can follow you.
  5. Finish. Click Mark work done. The client confirms completion and can leave a review.

Every job card also has Message client and Report issue.

14.4 Service history

Service history is a read-only record of your completed and cancelled jobs, with totals and your average rating. Clear booking removes a job from the list.

14.5 Messages & Assistant

These work exactly as for clients (sections 13.12 and 13.13): chat privately with your clients, and ask the Technician assistant how to accept jobs, update availability or get verified.

Chapter 15 · Role guide

Administrator guide

Keep the platform trustworthy. Log in with admin@workman.local.

15.1 Overview

Counters for total users, clients, technicians, pending verifications, approved technicians, categories, bookings and reviews, followed by shortcuts to each administration page. Review technicians jumps straight to the queue.

15.2 Verification — approving technicians

  1. Open Verification. The Pending tab lists technicians waiting for review (tabs: All / Pending / Approved / Rejected).
  2. Check the phone, experience, city and bio, and open the uploaded identity document (a warning is shown if none was uploaded).
  3. Click Approve — the technician immediately appears in client searches — or Reject.

15.3 Users

Search by name or email and filter with the tabs All / Clients / Technicians / Administrators. Click Deactivate to block an account (the person can no longer log in) and Reactivate to restore it.

15.4 Categories

  • Create a category with a name and optional description, then click Create category.
  • Categories requested by technicians show Pending review with Approve / Reject.
  • Deactivate hides a category from clients without deleting it; Activate brings it back; the red bin icon deletes it.

15.5 Bookings, Reviews and Reports

  • Bookings — a read-only view of every booking on the platform with client, technician, service, date, transport fee and status.
  • Reviews — read all ratings and comments; click Remove review to delete an abusive or fake review (the technician's rating is recalculated).
  • Reports & issues — issues submitted by clients and technicians, with reporter, type, description, date and status. Write Admin resolution notes and click Mark as Resolved.

Appendix B

Testing the API with Postman

The postman/ folder contains a collection that walks the whole platform — all three roles and the full booking lifecycle (32 requests, 83 assertions). With the backend running and freshly seeded:

$ php artisan migrate:fresh --seed       # in backend/ — start from clean demo data
$ npx newman run postman/workman-api.postman_collection.json   # from the project root

Or import postman/workman-api.postman_collection.json into the Postman app and use the Collection Runner. API requests authenticate with Authorization: Bearer <token>, where the token is returned by POST /api/auth/login. The full route list is in backend/routes/api.php.
